# End-to-end results: spindoctor-qwerty-cursor 1.1.0

Run on 2026-10-11 (PT) in a clean-room copy (empty folder, empty HOME, `env -i` with PATH=/usr/bin:/bin, no access to engine
development folders), following only this README: `python3 tools/install_local.py` (which installed into
`~/.cursor/plugins/local/spindoctor-qwerty`), then `tests/cursor_host_check.py`.

**Mode: host-simulated.** The real **Cursor CLI** (`cursor-agent` 2026.10.01-e373342, from the official installer at
cursor.com/install) was installed on a Linux test machine and used without an account, sign-in or API key. It loads plugins only in
a signed-in session: `cursor-agent -p --plugin-dir <plugin>` answers "Authentication required", `cursor-agent mcp list` reads only
`.cursor/mcp.json` / `~/.cursor/mcp.json` and doesn't list plugin servers, and `plugin marketplace` commands need an account. Its
model endpoint is Cursor's own service, so a local stand-in model can't be used either. The Cursor IDE also needs an account. So the
check stands in for Cursor: it validates the manifest, folder-based component discovery and front matter against the plugins
reference, installs with `tools/install_local.py` into a throw-away home, discovers the installed copy the way the reference
describes, expands `${CURSOR_PLUGIN_ROOT}` in command/args/env/cwd, starts the MCP server and runs the full end-to-end suite through it.

**Format check:** the Cursor plugins reference (cursor.com/docs/reference/plugins, read 2026-10-11) supports two formats: Agent
Plugins (root `plugin.json`, skills + MCP only, and Cursor does **not** expand `${PLUGIN_ROOT}`/`${PLUGIN_DATA}`) and Cursor Plugins
(`.cursor-plugin/plugin.json`, with rules, agents, commands, hooks and variables). This repo uses the Cursor Plugin format so the
rule, agent and commands load, with `${CURSOR_PLUGIN_ROOT}` in `mcp.json`. Local testing is documented as copying into
`~/.cursor/plugins/local/<name>` (outside symlinks are skipped) (cursor.com/docs/plugins).

**Parity target:** the updated SpinDoctor 3.1.2. Publishing was approved by Russell on the basis of the updated 3.1.2 passing its
own suite 18/18, with the three 29-qubit test checks adapted to the 298-qubit limit.
